# 卡文识别、翻译与 Lua 实现

## 来源和身份

网页可能同时展示新卡、再录、规则补充和商品宣传。保留每张卡的来源对应关系，独立卡图优于整页截图。官网无法自动读取时用可用的浏览工具；仍不可访问时处理用户提供的本地图，不宣称已核对看不到的官网。

名称、发行编号、正式卡密、临时 ID 是不同信息。卡密是识别编号，不应描述为由卡名计算的哈希。后来公开的正式数据优先于预览资料；不确定的编号不能写成正式编号。

宣传图须找出完整卡片边界，排除卡面之外的商品、背景和宣传文字。小字号放大不会增加原始信息，读不清需找原文或请用户补充。

卡图保留样本水印，记录原图来源、哈希及裁切坐标，封包为 `pics/<ID>.jpg`。裁切坐标是 EXIF 方向校正后的像素，右、下边界不包含在区域中。

## 翻译和字段

保留原文卡名和完整卡文。已有民间译名可沿用用户习惯；新译名说明是暂译，允许时保留原名。不把音译选择当作效果未决项反复询问。

字段以 CDB `setcode` 为基础，结合官方卡名、注音及“规则上也当作……”处理。中文名缺少某字不代表没有字段，日文汉字无关也不代表没有注音字段；必要时分别保存原名和注音。

## 逐条效果的实现记录

每条效果记录原文、翻译、时点、位置、费用、对象、步骤、次数/召唤限制及对应 Lua 函数。检查方向：

- “发动”一次、“使用”一次、每卡一次、同名卡一次；编号共用或独立限制。
- 费用、条件、取对象、处理时选择，不能给无取对象效果擅自加取对象。
- “之后”“并且”“若如此做”的执行依赖；精确数量与“最多”的区别。
- 特殊召唤手续、融合素材、仅可某种方式召唤及正规召唤后的苏生资格。
- 整回合限制是否包含发动前行为，是否需要 oath、activity counter 或引擎特定辅助函数。
- 离场前/处理时信息、攻守比较时点、无效和免疫。
- 当前区域及类型：在魔陷区的卡可能满足点名“某卡”，但不满足“怪兽”的当前类型条件。

这些不是所有卡必须具备的结构。复杂场景依同引擎成熟脚本及公开裁定确定，不能只凭自然语言设计一个看起来合理的函数。

## 客户端兼容

先读目标 `constant.lua`、`utility.lua` 及实际辅助脚本。确认 `GetID()` 返回值、同名次数限制的辅助偏移及特殊召唤手续 API。不要未检查就引入其他分支的 `Fusion.AddProcMix` 等函数。

搜索功能相近的两三张卡，不加载全部脚本。记录参考 ID、函数和适用原因。引用上游代码时保留相应许可/署名。分享工具不夹带整个客户端、卡库或官方卡图；实际制作的卡片工程可独立交付。

## 验证层次

1. 来源：识别、翻译、参数、图片对应。
2. 包结构：CRC、`datas/texts` ID、脚本/图片、哈希。
3. Lua 语法：目标版本 `luac -p` 或等价解析器。
4. 引擎运行：加载和 API 可用。
5. 效果场景：时点、不能发动条件、费用、对象、连锁干扰、区域变化、次数限制。

前三级不证明后两级。工具自动检查第二级、可选第三级，清单把效果标为 `not_verified`。实测报告另存引擎版本、输入、实际结果和时间，不能只写没有证据的“通过”。参考脚本同样需要结合目标引擎验证，构建成功和测试数量不是效果正确性的证据。

卡文及裁定以当前任务的官方来源为准。技术资料：[YGOPro 脚本](https://github.com/Fluorohydride/ygopro-scripts)、[引擎 API 源码](https://github.com/Fluorohydride/ygopro-core)。
